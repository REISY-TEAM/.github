# Support

This file explains where to ask for help across REISY repositories.

## Product or code questions

Open an issue in the repository that owns the code, documentation, or decision you are asking about.

A good support issue includes:

- What you were trying to do.
- What happened.
- What you expected to happen.
- Relevant logs, screenshots, or links.
- Environment details, when relevant.

Do not include secrets, private user data, provider credentials, or production data in support issues.

## Contribution questions

For questions about contributing, start with:

- `CONTRIBUTING.md`
- The repository README
- Existing issues and pull requests
- Repository-specific docs

If the answer is still unclear, open a focused issue in the relevant repository.

## Security issues

Do not open a public issue for vulnerabilities, exposed secrets, or private data leaks. Follow `SECURITY.md`.

## Provider and integration issues

For travel, map, payment, analytics, or infrastructure providers, avoid posting private credentials, contracts, partner terms, dashboards, or unpublished pricing.

When reporting provider issues, include non-sensitive details such as provider name, endpoint category, timestamp, environment, request ID if safe, and high-level error behavior.

## Governance issues

Questions about organization-wide contribution rules, PR templates, or PR governance workflows belong in this `.github` repository.
